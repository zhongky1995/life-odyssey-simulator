# 三条路怎么写，模拟怎么走

## 1. 一条路不只是一个岗位

每条路都要写出未来五年的工作方式、主要身份、会积累什么，以及要承受什么。只换一个职位名称，不算一条新路线。

生成时可以从三个方向找差异：

- 沿着现在的积累继续往上走。
- 把已经会的东西带到另一个领域。
- 换一种工作方式，例如从组织内走向顾问、组合职业或创业。

这只是找方向的方法，不是固定模板。如果用户心里的三种可能本来就是管理、专家和创业，就按这三条写。

## 2. 每条路内部要有的内容

```yaml
name:
one_line_promise:
five_year_identity:
entry_move:
existing_assets:
new_capabilities:
year1_state:
year3_state:
year5_daily_work:
gain:
cost:
largest_unknown:
reversibility:
```

路线名字要贴着用户的说法。不要固定叫“延展路线”“转型路线”“理想路线”，也少用“重构、跃迁、破局、赋能”这类放在哪都成立的词。

## 3. 三条路要真的不一样

下面这些方面，至少要有两项存在明显差别：

- 主要身份：专家、管理者、经营者、顾问、创作者等。
- 工作环境：组织内、自由职业、组合职业、创业等。
- 最看重的回报：稳定、收入、影响力、自主、创造、专业深度等。
- 必须付的代价：波动、责任、重复、重新学习、关系成本、时间投入等。
- 五年后最值钱的能力。
- 五年后还能转去哪里。

如果只是同一方向换了三家公司或三个相邻职位，回去重写。

三条路都要有让用户心动的理由，也都要站得住。不要把第一条暗写成正确答案，第二条写成退路，第三条写成不用考虑现实的梦想。

## 4. 先让用户改三条初稿

开始时每条只说一句。可以这样问：

- “哪条你一看就觉得不像自己？”
- “有没有一条你其实想过，但这里没写到？”
- “这里有没有两条其实差不多？”

用户可以删、合并、换名字或补一条。没让用户看过的路线，不能直接写进最终卡片。

## 5. 每条路怎么模拟

通常做两次选择，再写一个第五年的普通工作日。

### 进入后的 6～12 个月

需要交代：

- 用户是怎么走进这条路的。
- 一周大部分时间在做什么。
- 已经得到的一样东西。
- 第一件让人不舒服或后悔的事。
- 两到三个都说得通的选择。

每个选项都必须有所得也有所失，不能把正确答案藏在措辞里。

### 第三年

写出：

- 一个符合这条路的机会。
- 一个由这种工作方式带来的麻烦或代价。
- 一项已经越用越熟的能力。
- 第二次需要取舍的选择。

机会和代价要从用户的角色、现实条件和前一次选择里长出来，不靠裁员、暴富、贵人出现等戏剧性事故硬推剧情。

### 第五年的一个普通工作日

把抽象职业名落到日常：

- 周一早上先处理什么。
- 谁定优先级，谁评价结果。
- 时间和注意力主要由谁安排。
- 哪项能力变成了吃饭的本事。
- 得到什么，又放弃什么。
- 这五年让选择变多了，还是变少了。

用户要判断的是这种日子能不能过，不是看一段成功人士简介。

## 6. 场景怎么写才像真的

- 用第二人称和现在时，多写工作动作，少写抽象结论。
- 一次只走一个节点。不要在一条消息里写完五年，也不要写成小说预告片。
- 开头直接进入事情，不用“时间来到第三年”“命运的齿轮”“你终于站在新的起点”等铺陈。
- 不用“你会发现”“这意味着”“真正的挑战是”替用户下结论。把发生的事和选择摆出来，让用户自己说感受。
- 每次控制在用户一眼能看完、马上能选的长度。
- 只用当前对话里已经知道的内容。没有精确收入，就只写上升、下降、波动等相对变化。
- 涉及领导、同事或客户的想法时，说明这是为了模拟暂时设定的条件，不假装知道真实人物的内心。
- 不保证路线成功，也不要靠连续倒霉来逼用户放弃某条路。
- 用户改正了前提，后面的场景跟着改，不继续维护旧版本。

## 7. 每次选择后，内部记什么

```yaml
route:
stage:
choice:
reason_in_user_words:
accepted_gain:
accepted_cost:
new_signal:
confidence: confirmed | tentative
```

一次选择只能说明“这一次他选了什么”。只有相似选择在几条路里反复出现，或用户自己确认，才能写成较稳定的偏好。

## 8. 走完一条路后怎么问

一次只挑一两个问题，不要问完一整组：

- “哪一段日子，你读着会觉得‘这样上班好像可以’？”
- “哪件事一出现，你就不太想走这条路了？”
- “如果得忍受这件事，换来的东西对你够不够值？”
- “这条路是不是被我们想得太顺了？”

三条都走过后，再回头看：

- 几次都选了什么。
- 哪种代价每次都躲开了。
- 换了路线，什么还是很重要。
- 哪项能力走哪条路都用得上。
- 哪个问题只要弄清楚，选择就会容易很多。

## 9. 最后的小尝试

它应该比正式转型便宜、快，也更容易退回来。可以考虑：

- 找目标路线里的真实从业者聊一次，问题提前写好。
- 在当前工作里短期接一件目标角色会做的任务。
- 花 1～2 周做一个小项目。
- 接一单范围明确、风险不高的真实委托。
- 发一个公开作品，看看别人是否能理解这项能力，也是否有人需要。

内部记录：

```yaml
hypothesis:
action:
time_cost:
money_or_reputation_risk:
evidence_to_collect:
continue_if:
adjust_if:
stop_if:
```

对用户不要念这组字段。用普通话商量：想弄明白什么、具体做什么、要花多少、看到什么算有用，以及什么情况下不再继续。

“报一门课”“再想想”“把计划写得更完整”单独拿出来通常不算试，因为它们没有让用户碰到那条路的真实工作。
