# 文字结果、标题和手机竖版卡片

## 1. 先交什么，后交什么

1. 先把完整文字结果发给用户。
2. 从用户说过的话里写三个标题，请用户选一个或自己改。
3. 标题确认后，再整理卡片 JSON。
4. 环境允许时，生成 1080×1440 的 SVG 和 PNG。
5. 检查成图。直接展示 PNG，让用户在手机上能点开看大图；另附 SVG 源文件。

图片做不出来，不影响文字结果。不要为了塞进卡片删掉重要的未知，也不要把没有确认的猜测写成结论。

## 2. 完整文字结果

可参考下面的顺序，但小标题要顺着用户的说法改，不必每次逐字照搬：

```markdown
# {用户确认的标题}

> 人生奥德赛

## 我为什么开始想这件事

## 先把现在的情况说清楚
- 我已经确定的
- 这件事会牵动哪些生活方面
- 我不想轻易放掉的
- 还有哪些地方没把握

## 三种生活
### {版本一的名字}
### {版本二的名字}
### {版本三的名字}

每种写清：生活的主要安排；怎样起步；第一年、第三年、第五年的普通日常；我想要什么；我要承担什么；还有什么需要亲自弄清。

## 模拟里，我是怎么选的

## 把几次选择放在一起看

## 还有哪些事，只有试过才知道

## 先小范围试一下
- 想弄明白什么
- 准备怎么试
- 看什么结果
- 什么时候继续、调整或停下

---
这三种生活都不是预测。只是把几种选择往前推了几年，看看哪种普通日子更像我愿意过的。
```

不要复述整场聊天。写重要判断时，带上一处具体来由，例如用户说过的经历，或他在某种生活里刚做的选择。

## 3. 标题怎么写

“我的人生奥德赛”“三种人生路线”“探索无限可能”只能做栏目名，不能做主标题。

先从这些地方找标题：

1. 用户自己说过、读起来有他口气的一句话。
2. 他在几种生活里都不肯放掉的一件事。
3. 两件都想要、却很难同时拿满的东西。
4. 现在还没有答案，但用户确实想继续追问的问题。

写三个不同角度的候选：一个尽量贴近原话；一个把难取舍的两件事说清；一个让不了解前情的人也能看懂，同时不暴露隐私。只给用户看标题本身，不要标“原话型、矛盾型、分享型”。

标题前可以补一句来由，例如：“我用了你刚才那句‘想把日子过慢一点’，写了三个版本。”不要写成标题策略说明。

标题需要满足：

- 通常 8～28 个中文字符，能在卡片上自然换成两行。
- 换到另一个人身上，不能原样成立。
- 不出现公司、人名、住址、精确资产、疾病或关系隐私。
- 用户还没选定哪种生活时，不把其中一种写成既定结果。
- 不制造年龄焦虑，也不写空泛励志句。
- 少用“真正的、终于、重新定义、找到答案、看见可能、勇敢出发”等总结腔；除非那就是用户原话。

下面这些主标题直接拒绝：

- 我的人生奥德赛
- 三种可能的人生
- 遇见更好的自己
- 探索人生的无限可能
- 勇敢开启人生新篇章

## 4. 卡片里放什么

卡片不是缩小版报告。用户点开后，只需要看到：这次在想什么、三种生活分别怎样安排、每种为什么吸引人又要付出什么，以及几次选择里反复出现的一件在意。

卡片里不要放 1/3/5 年时间线、模拟依据、评分、未知项、小尝试、“下一步”或行动清单。这些只留在完整文字里。

卡片上的栏目名用短句，不用固定抒情句。避免“共同照见”“写给未来的自己”“答案正在发生”“这就是你真正想要的”等可替换给任何人的话。

## 5. 卡片 JSON

`versions` 必须正好三条：

```json
{
  "title": "用户确认的标题",
  "title_status": "confirmed",
  "share_safe": true,
  "eyebrow": "人生奥德赛",
  "versions": [
    {
      "name": "这种生活的名字",
      "summary": "一句话说明未来主要怎样生活",
      "gain": "我想要的",
      "cost": "我要承担的"
    }
  ],
  "insight": "一句用户已经确认、在几种生活里反复出现的在意"
}
```

`title_status` 只能是 `confirmed` 或 `corrected_confirmed`；`share_safe` 必须为 `true`。否则渲染器拒绝生成卡片。

## 6. 生成卡片

```bash
node scripts/render_odyssey_card.js \
  --input /absolute/path/to/odyssey-card.json \
  --output /absolute/path/to/odyssey-card.svg \
  --png /absolute/path/to/odyssey-card.png
```

脚本读取 Skill 自带的三三正式 Logo，并把原文件内容嵌入 SVG。不要重画或修改 Logo。

PNG 是用户查看和分享的默认格式，SVG 是源文件。如果当前环境不能转出 PNG，可以先交 SVG，并说明情况。

## 7. 版面要求

- 画布固定为 1080×1440，内容从上到下排成一列，不需要横向滚动。
- 只放标题、三种生活、各自想要的部分与需要承担的代价，以及一句最后确认过的总结。
- 手机点开后要能轻松读清，不靠缩小字号塞内容。
- 三种生活使用同一层级，不通过颜色、顺序或措辞暗示哪种最好。

## 8. 出图前检查

- Logo 来自正式资产，没有拉伸或变形。
- 主标题是用户最后确认的版本，不是栏目名或通用励志句。
- 三种生活都出现了，也没有一种被暗写成正确答案。
- 每种生活的简短说明至少涉及两个与本次问题相关的方面，而不只是岗位名。
- 图片里只有一句最终总结，没有“下一步”、行动清单或整份报告的压缩复刻。
- 没有文字溢出、裁切、乱码或小到看不清。
- 文字版和卡片使用同一份确认内容。
- 没有公司、人名、住址、精确资产、疾病或关系隐私。
- 栏目名和总结读起来像这个用户会认领的话，不像课程口号或 AI 金句。

内容太长时，缩短卡片文案，保留完整文字报告。不要靠缩小字号硬塞。交付时优先内嵌 PNG 大图，并附 SVG 源文件链接。
