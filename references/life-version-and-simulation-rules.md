# 三种生活怎么写，模拟怎么走

## 1. 一种人生版本不只是一个身份

每种版本都要写出未来五年的生活重心、普通日常、维持生活的方式、重要关系、时间安排，以及要承受什么。只换一个岗位、城市或身份名称，不算完整的新版本。

生成时可以从三个方向找差异：

- 保留现在的主线，但改变节奏、边界或生活安排。
- 换一条主要路径，让工作、居住或关系重新组合。
- 放下一个一直被当作前提的条件，尝试另一种生活结构。

这只是找方向的方法，不是固定模板。三种生活必须来自用户实际想过的事、已有资源和能承受的范围。

## 2. 每种生活内部要有的内容

```yaml
name:
one_line_picture:
central_choice:
focus_domains: []
entry_move:
existing_resources:
new_capabilities_or_habits:
year1_state:
year3_state:
year5_ordinary_week:
gain:
cost:
largest_unknown:
reversibility:
```

版本名字要贴着用户的说法。不要固定叫“稳定版、转型版、理想版”，也少用“重启人生、打破边界、向内生长、活出自我”等放在哪个人身上都成立的词。

## 3. 三种生活要真的不一样

下面这些方面，至少要有两项存在明显差别：

- 生活的主要重心放在哪里。
- 工作、收入和支出的安排。
- 时间由谁决定，忙与闲怎样分布。
- 住在哪里，是否需要移动。
- 与家人、伴侣、朋友或社群怎样相处。
- 身体与精力会承受怎样的日常。
- 五年后积累了什么，也放弃了什么。
- 五年后还能转去哪里。

如果只是同一种生活换了三个城市、三家公司或三个收入数字，回去重写。

每种生活至少覆盖两个与本次问题有关的方面，并说明它们怎样互相影响。比如换城市不只改地址，还可能改变收入、通勤、照顾责任和常见的人；只写好处不算完整。

三种生活都要有让用户心动的理由，也都要站得住。不要把第一种暗写成正确答案，第二种写成退路，第三种写成不用考虑现实的梦想。

## 4. 先让用户改三种初稿

开始时每种只说一句。可以这样问：

- “哪种生活你一看就觉得不像自己？”
- “有没有一种你其实想过，但这里没写到？”
- “这里有没有两种其实差不多？”

用户可以删、合并、换名字或补一种。没让用户看过的版本，不能直接写进最终卡片。

## 5. 每种生活怎么模拟

通常做两次选择，再写一个第五年的普通星期。

### 进入后的 6～12 个月

需要交代：

- 用户是怎么走进这种生活的。
- 住在哪里，一周大部分时间怎样分。
- 收入、关系、身体精力等相关方面发生了什么变化。
- 已经得到的一样东西。
- 第一件让人不舒服或后悔的事。
- 两到三个都说得通的选择。

每个选项都必须有所得也有所失，不能把正确答案藏在措辞里。

### 第三年

写出：

- 哪些安排已经成为稳定日常。
- 一个符合这种生活的机会。
- 一个由这种生活结构带来的麻烦或代价。
- 一项已经越做越顺的能力、习惯或关系。
- 第二次需要取舍的选择。

机会和代价要从用户的现实条件与前一次选择里长出来，不靠暴富、重病、分手、贵人出现等戏剧性事故硬推剧情。

### 第五年的一个普通星期

把抽象人生写成能判断的日常：

- 周一早上在哪里醒来，先做什么。
- 靠什么维持收入与支出。
- 时间主要花给哪些人和事情。
- 身体与精力通常是什么状态。
- 哪些事情由自己决定，哪些仍受别人或现实限制。
- 得到什么，又放弃什么。
- 这五年让选择变多了，还是变少了。

只写与本次问题有关的方面，不需要给每种生活补齐伴侣、孩子、房子、事业成就和兴趣爱好。用户要判断的是这种日子能不能过，不是看一段完美人生简介。

## 6. 场景怎么写才像真的

- 用第二人称和现在时，多写日常动作，少写抽象结论。
- 一次只走一个节点。不要在一条消息里写完五年，也不要写成电影预告。
- 开头直接进入事情，不用“时间来到第三年”“命运的齿轮”“你终于站在新的起点”等铺陈。
- 不用“你会发现”“这意味着”“真正的答案是”替用户下结论。把发生的事和选择摆出来，让用户自己说感受。
- 每次控制在用户一眼能看完、马上能选的长度。
- 只用当前对话里已经知道的内容。没有精确收入，就只写相对变化；没有健康依据，就只写用户描述过的精力和生活影响。
- 不替伴侣、家人、医生、雇主或机构编造态度与承诺。如需设定他人的反应，明确说明只是这轮模拟的条件。
- 不保证某种生活成功，也不要靠连续倒霉来逼用户放弃。
- 用户改正了前提，后面的场景跟着改，不继续维护旧版本。

## 7. 每次选择后，内部记什么

```yaml
life_version:
stage:
choice:
reason_in_user_words:
accepted_gain:
accepted_cost:
affected_domains: []
new_preference:
confidence: confirmed | tentative
```

一次选择只能说明“这一次他选了什么”。只有相似选择在几种生活里反复出现，或用户自己确认，才能写成较稳定的偏好。

## 8. 走完一种生活后怎么问

一次只挑一两个问题，不要问完一整组：

- “哪一段日子，你读着会觉得‘这样过好像可以’？”
- “哪件事一出现，你就不太想选这种生活了？”
- “如果得承担这件事，换来的东西对你够不够值？”
- “这种生活是不是被我们想得太顺了？”

三种都走过后，再回头看：

- 几次都保住了什么。
- 哪种代价每次都躲开了。
- 换了生活，什么还是很重要。
- 哪项准备走哪条路都用得上。
- 哪个问题只要弄清楚，选择就会容易很多。

## 9. 最后的小尝试

它应该比正式改变生活便宜、快，也更容易退回来。可以考虑：

- 按目标生活的作息过一个周末或一周。
- 在目标城市短住，并按真实预算、通勤和工作节奏生活。
- 体验一种新的工作、学习、照顾或创作安排。
- 与会被决定影响的人进行一次有明确问题的沟通。
- 用一笔事先限定的时间或预算，测试某种生活是否真的适合。

内部记录：

```yaml
hypothesis:
action:
time_cost:
money_relationship_or_health_risk:
evidence_to_collect:
continue_if:
adjust_if:
stop_if:
```

对用户不要念这组字段。用普通话商量：想弄明白什么、具体做什么、要花多少、看到什么算有用，以及什么情况下不再继续。

高风险、不可逆或需要医疗、法律、投资专业判断的动作不能作为实验。“再想想”“把计划写得更完整”也不算，因为它们没有让用户碰到那种生活的真实日常。
